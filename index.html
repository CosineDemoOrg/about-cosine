What Cosine is

Cosine is an AI assistant optimized for practical engineering work. Instead of stopping at advice, it can directly modify your codebase, run commands, and validate results.

Terminal-based

Operates like a colleague in a terminal session: reads files, edits code, runs builds/tests, and reports what was verified.

Repo-aware

Follows existing conventions (naming, formatting, patterns) and avoids unnecessary churn.

Change + verify

Doesn’t claim success without checking. When it changes code, it should run relevant tests or demos.

Minimal retrieval

Reads the minimum set of files needed to complete the task, using targeted searches when location is unclear.

How it works (high level)

  1. Locate the relevant code using file search and targeted reads.
  2. Change code with small, consistent edits that match your style.
  3. Verify via tests/builds, or a focused repro script.
  4. Explain the commands it ran and the reasoning for non-trivial decisions.

Cosine is happiest when you give it a clear outcome (bug report, feature request, or acceptance criteria).

Core capabilities

Codebase navigation
  • Find files by name patterns and search within file contents
  • Read only what’s needed to complete the current step
  • Infer conventions from nearby code (imports, formatting, APIs)
Safe, incremental edits
  • Prefer small diffs and clear intent
  • Avoid replacing large blocks with TODOs
  • Respect existing comments, quotes, whitespace, and structure
Verification
  • Run appropriate tests and builds
  • When tests don’t exist, create a minimal repro/validation
  • Report what was actually run and observed
Web + docs research (when needed)
  • Look up latest versions and API docs before adding dependencies
  • Prefer official docs; cite sources when summarizing

Typical workflow

A good request includes: what you want, where it lives (if you know), and how to verify.

Example: bug fix

  • You: “Login fails with 500 when email has a plus sign.”
  • Cosine: reproduces, finds the handler, patches parsing
  • Cosine: runs unit/integration tests or adds a targeted test

Example: feature

  • You: “Add CSV export to the users table.”
  • Cosine: finds table component + API route, adds export
  • Cosine: adds/updates tests and verifies locally

FAQ

What makes Cosine different from a chat-only assistant?

It’s built around an engineering loop: modify the repository, validate with real commands, and communicate what was verified.

Will Cosine add lots of new files or dependencies?

It prefers minimal changes. New dependencies should be justified, aligned with project conventions, and verified.

How do I get the best results?

Provide a clear outcome, constraints, and a way to verify (tests, steps, expected output). If you know the file or folder, mention it.

What does “minimal retrieval” mean in practice?

Read the smallest set of files necessary to finish the current step, rather than scanning the whole repository “for context”.
